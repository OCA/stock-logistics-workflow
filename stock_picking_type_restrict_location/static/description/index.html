Stock Picking Type Restrict Location

Operation types have a default source and destination location, but the locations of a transfer can be changed freely afterwards, so a transfer can end up moving stock between locations that have nothing to do with its operation type. This module adds an option on operation types to restrict their transfers to those locations: the source and the destination of the transfer must be the default locations of the operation type or one of their sublocations. A vendor or customer location is not restricted.

Configuration

To restrict the locations of an operation type:

  1. Enable Storage Locations in Inventory > Configuration > Settings.
  2. Go to Inventory > Configuration > Warehouse Management > Operations Types and open the operation type.
  3. Check its Source Location and Destination Location: they are the locations its transfers will be restricted to. A vendor or customer location is not restricted.
  4. Enable Restrict Location.

The option cannot be enabled, and the locations of a restricted operation type cannot be changed, while transfers in progress or rules of that operation type use other locations. The message names the transfers, or the first rule, to finish, cancel or correct first. The option can always be disabled.

The Unrestricted Locations filter of the operation types list shows the ones that are not restricted.

Usage

On the transfers of a restricted operation type:

  • The Source Location and the Destination Location only offer the locations of the operation type and their sublocations.
  • A transfer with any other location is rejected with a blocking message, also when it is not created by hand.
  • A return created from a transfer can go back the way that transfer came, even when it uses the same operation type: its source can be inside the destination of the original transfer, and its destination inside the source of the original transfer.
  • When the source or the destination of the operation type is a vendor or a customer location, that side of the transfer is not restricted.

Transfers that are done or cancelled are not checked.

The rules of a restricted operation type cannot take stock from locations outside its source location. Their destination is checked when it becomes the destination of the transfer: on push rules, except the ones that add no step, and on rules that take the destination location from the rule. Pull rules that send stock to a production location are not checked: they describe the components consumed by manufacturing orders, not transfers.

The transfers of the other operation types keep the standard behavior.

Known issues / Roadmap

  • Only the source and destination locations of the transfer are checked. The standard views limit the locations of its operations to sublocations of those, but they are not checked when they are set by other means.
  • Only the returns created from a transfer, and their backorders, can go back the way the original transfer came. Other reverse transfers need the operation type to have a Returns Type that allows them: the one created when the demand of a partially processed move is reduced, the refunds of a point of sale, or a copy of a return (a duplicate, or the transfer created when part of a return is split or added to a wave).
  • The transfers that resupply a subcontractor go to the subcontracting location of that partner. An operation type used for them should not be restricted when subcontractors have their own location outside its destination location.
  • Odoo sets the default locations of the operation types of a warehouse again when the warehouse is reconfigured, for example when its steps or its short name change, or when some modules are installed. That reconfiguration is rejected while transfers in progress or rules of its restricted operation types do not fit the resulting locations, also when the locations of an operation type had been customized and Odoo sets the standard ones back.
  • Moving a location under another parent location, or changing its type, does not check the transfers and rules that use it.
